已定位截图中横向暗带的主要渲染原因，并修复独立的源拓扑权重缺陷。本报告不是下半身整体视觉 PASS；残余局部几何、分区法线边界和历史接触失败分别保留。

## 1 · 主要暗带：截图宿主没有真正运行 Skin Cache
主工程配置开启 r.SkinCache.CompileShaders，但独立截图宿主实际为 0；Mode=1、RecomputeTangents=2 不能替代这个前置条件。仅强制 RecomputeTangents=1 的旧实验因此不足以排除法线问题。

固定旧资产、实际骨骼矩阵、相机和底光，只在启动时开启 Skin Cache 编译后，右臀中段原来的暗后突然变亮条带消失。关闭 AO、接触阴影和动态阴影则不改变原图。原来的法线排除结论已更正。

测量灰模后视图 x=403..431：第 308 行到第 312 行的亮度反弹，从 +15.23 变为 -4.76（0–255 标度）。这是图像亮度证据，不是几何误差或临床指标。截图仍保留局部形状不规则，不能说全部折痕均已消失。

## 2 · 为什么左右表现不同
固定的 C1.5 VaM 原始 pre-skin 采样证明，Preset_QiMeng-b 本身并不镜像。源顶点 8249 / 18920 的高度差为约 2.248 cm；逐 Morph 分解将这一差异定位到 a07 - Body，值为 1。另两对诊断点分别约 1.576 / 1.453 cm。UE 生成输入与这些 VaM 采样在浮点误差内一致。

这种源形态差异会改变臀下表面的朝向、区域支撑和变形后法线。它解释了左右敏感度不同的输入基础；不能据此将所有残余轮廓问题归为“正常”，也不能复制左臀覆盖右臀。

## 3 · 独立工程缺陷：按 UV 副本扩散支撑
调用链：GluteStructureBuilder 的区域扩散 → Measure / 辅助骨权重 → LegJiggleBuilder::WeldWeights → 最终蒙皮。

旧扩散图只用一条连边连接副本，未统一拆开的三角形邻域。源点 7189 的两份区域权重为 0.26751 / 0.21125；源点 17896 为 0.39182 / 0.30554。Leg Weld 按邻接面积选择代表，左侧选中较小值，右侧选中较大值。这个选择与组织力学无关。

修复：按有来源证明的 Source ID 建立逻辑拓扑，用完整唯一邻域执行八轮扩散，再分发给有三角形引用的副本；保持未引用顶点零权重、原有支撑体系及原始体型不对称。不同位置的同 ID 输入明确拒绝，未做距离焊接或全局表面平滑。

| 验证范围 | 修复前最大副本差 | 修复后 |
|---|---:|---:|
| 左侧 91 个有效副本组 | 0.128491 | 0 |
| 右侧 109 个有效副本组 | 0.123233 | 0 |

单独修复权重并没有消除截图横纹，所以它不是该横向暗带的唯一或主要渲染原因。
