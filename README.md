## 打开与使用

1. 本插件包含 C++ 编辑器模块，首次使用必须编译。需要 Visual Studio C++ Build Tools 和 UE 5.8 支持的 Windows SDK。运行本目录的 `Build.ps1`，默认引擎路径是 `I:\Program\Epic Games\UE_5.8`。
2. 编译成功后重启 UE。在插件管理中启用 **VaM Resource Browser**，从 **窗口 → VaM 资源浏览器** 打开可停靠面板。
3. 点击面板上方“选择 VaM 目录”，或在面板内填写根目录并“应用目录”。本机默认识别 `F:\Virt A Mate`。
4. 初次扫描后，预设标签页默认显示用户保存的松散预设；左侧选择其他文件夹可以浏览包内预设。文件夹列表本身也分页，每组 100 个，可搜索。
5. 头发、服装、皮肤 / 纹理、Morph 使用独立标签页。搜索支持名称、作者、包、标签和路径；多个关键词按“同时包含”匹配。另有来源、作者、标签过滤和名称 / 时间排序。
6. 默认每页 48 条。进入可视区才请求缩略图；翻页释放旧页面图像并取消旧请求。没有缩略图的卡片显示名称。单击条目才解析描述详情。
7. “增量扫描”复用未变更来源。“重建索引”重新读取全部轻量元数据。勾选“自动检查变化”后，每 60 秒检查来源文件数、路径、大小和修改时间，更新新增 / 修改来源并清理已删除来源，不重复读取未变化包。

## 分类与支持边界

- `Custom/Atom/Person/.../*.vap`：外观、发型、服装、皮肤、Morph、姿势、人物、动画、胸部物理、臀部物理、插件等分类预设。
- `Custom/Hair/.../*.vap` 与 `Custom/Clothing/.../*.vap`：单件发型 / 单件服装预设，与整个人物的装备预设分开。
- `Saves/Person/<分类>/*.json`：旧版人物预设，按目录区分外观和姿势等。
- `Custom/Clothing/.../*.vam`、`Custom/Hair/.../*.vam`：服装和发型描述。
- `Custom/Atom/Person/Morphs/.../*.vmi`：Morph 描述；不读取 `.vmb` 差异数据。
- `Custom/Atom/Person/Textures/` 与 `Custom/Textures/`：皮肤纹理文件。此阶段只索引单张纹理，不宣称已把它们重建成完整皮肤材质。
- `Saves/scene/*.json`：单独的场景文件标签，不把场景假定为一个人物。
- PNG / JPEG 使用同名配图；TGA / DDS 保留条目但不做缩略图解码。来源缺失作者或标签时明确显示“未标注 / 来源未提供”。
- 阶段 01 浏览扫描不读取 `.vaj/.vab/.vmb`，不解析依赖闭包。阶段 02 仅在生成计划时读取相关 `.vaj` 描述，并流式计算二进制文件哈希；不解码人物几何、不提取场景中的人物、不执行插件脚本。
- 松散文件使用文件系统创建时间。VAR 只有 ZIP 条目时间，界面明确注明它不等于可靠的原始创建时间。

## 存储与资源上限

全部派生文件位于本插件 `Saved/`，可在关闭面板后备份：

| 文件 | 用途 |
| --- | --- |
| `catalog.sqlite3` | 持久化资产、来源签名、诊断索引（WAL 模式） |
| `settings.json` | VaM 路径和自动检查设置 |
| `Thumbnails/` | 最近使用的原始缩略图缓存，256 MiB / 1,024 文件双重上限 |
| `service.log` | 轮转日志，单文件 1 MiB，保留 2 个备份 |
| `ready.json` | 当前本机服务地址，仅用于编辑器启动握手 |

扫描并发 1；本机 HTTP 请求并发 4；前端缩略图并发 2；每个 SQLite 连接缓存 4 MiB；元数据读取上限 256 KiB；选中详情上限 2 MiB；JSON 展示前 64 KiB。单张图片限制 8 MiB、16 MP、最长边 8192；浏览器将图片缩为最长边 300 像素再保留，最多保存当前页 48 张。大于限制的资源保留索引，并显示诊断，不强行解码。

大库的**持久化索引大小随资源数量增长**，不是无限保留的内存缓存。VAR 逐包处理，中央目录限制 64 MiB / 200,000 个条目。不会整体解压 VAR。

稳定标识由 VaM 根目录、来源相对路径和包内路径生成。不同包、不同版本、不同路径的同名条目共存。移动来源根目录或重命名来源文件会产生新标识；仅修改内容不会改变标识。

## 取消与故障

每个来源单独事务提交。取消会回滚正在处理的来源，保留本次已经完成的来源，并跳过删除清理。关闭面板会终止自有服务，SQLite 回滚未提交事务；再次打开可继续增量扫描。

损坏包不阻断其他包。已有索引的包如果随后损坏，保留上次可用条目并标记诊断；文件变化或手动重建时重试，临时 I/O 故障则在下一次扫描重试。目录不可访问或枚举失败时，不进行删除清理。文件在扫描期间发生变化时，下次扫描会重新检查。

“诊断”面板列出来源包、包内路径和错误；最多保存最近 2,000 条，每页 100 条。超出读取上限、无效 JSON、损坏 ZIP、图片解码失败都可以定位。

## 实现

编辑器模块创建 Slate 停靠标签和原生目录选择器，以 UE 内嵌 `SWebBrowser` 显示本地面板。后端使用**引擎自带 Python 3.11** 的标准库 SQLite / ZIP / HTTP，无需 Python 插件、pip、Node 或额外第三方包。服务仅监听 `127.0.0.1` 随机端口，每次启动随机会话令牌；限制来源、请求大小和文件读取范围，不加载远程页面。

引擎自带 Python 可执行文件必须存在：`Engine/Binaries/ThirdParty/Python3/Win64/python.exe`。

## 导入耗时与缓存

导入计划、解码/浏览器预览、来源材质解析和当前 UE 场景预览各有任务进度条。可确定总量的资源、部件和材质区显示已完成数量；来源核验、整体形状处理及 UE 编辑器单次耗时操作使用持续运行指示，不估算完成百分比。正式人物资产窗口同样显示校准、服装转移、资产生成和保存阶段；保存及独立重载期间取消能力按原有事务规则关闭。进度数据写在插件 `Saved/`，不参与来源 IR、材质或资产身份计算。

导入计划继续按来源锁和内容哈希生成；这一步通常不是主要耗时。Stage03 解码减少了逐个数值记录的内存复制和重复路径构造，但仍逐条检查截断、非有限数及最终 IR。来源材质解析会在先前的 SourceMaterialIR 中寻找同一来源贴图的 PNG；只有旧 PNG 的哈希和解码后像素都与本次来源完全一致才复用。新贴图使用无损 PNG 的较快压缩级别，像素、UV、材质语义不变。重新启动 UE 后，已保存的参考贴图和材质也会按资产路径加载。

正式人物构建只在来源 IR、计划、选定 Morph、相关代码和配置、锁定的 VaM 文件以及校准合同的完整哈希都吻合时复用已有 TriAx/形状校准。任何一项不吻合都会重新校准；含自定义目录 Morph 集的构建始终重新走来源解析。复用校准不跳过部件转移、UE 资产生成和保存/重新加载验证，因此首次导入或来源改变时仍需等待实际计算。`Saved/` 下的加速记录仅是可丢弃缓存，不作为资产来源。

## 人物调试面板

重新编译并启动 UE 后，从 **窗口 → VaM 人物调试** 或资源浏览器顶部的 **人物调试** 打开。选中场景中的 `VamCharacterActor` 后点击“使用选中人物 / 刷新”；也可点击“加载最新导入人物”，在当前场景生成临时预览实例。加载完成后，所有骨骼控制点直接叠加显示在人物身上。点击青色点，再用视口移动或旋转工具调整骨骼；黄色点表示当前骨骼。面板还提供骨骼名称筛选、局部位移/旋转数值编辑、逐骨骼与全姿态重置，以及所有可编辑 Morph 参数滑块。

骨骼姿态调整只保存在该人物实例的临时动画状态，不写入导入的骨架、网格或 Definition。Morph 调整使用现有预览参数接口，可用“恢复导入形状”复原。Stage06 另提供可放置人物、PBIK、刚体局部响应/布娃娃、Physics Handle 抓取、连续运动输入、主动呼吸和惯性见证区域；预览关卡与运行方法见 [STAGE06.md](STAGE06.md)。惯性见证不是肌肉或软体求解器；布料、头发和全身软组织仍待后续阶段。后续诊断工具与数据显示可继续加入该停靠面板。
